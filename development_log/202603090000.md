# PHPlus System Development Log

## 1. System Overview
PHPlus currently consists of two main components:
- `C:\PROJECT11\phplus-react`: frontend application (React + Vite) for staff/admin UI.
- `C:\PROJECT11\phplus`: backend service (FastAPI + MySQL) for authentication, health data, activity modules, QR attendance, and frontend build serving.

## 2. Frontend-Backend Integration
- Frontend uses same-origin API calls through `/api`.
- In development mode, Vite proxies `/api` to `VITE_API_BASE_URL` (default backend: `http://127.0.0.1:8000`).
- In build/deployment flow, `npm run build` in `phplus-react` will:
  1. generate `dist`
  2. copy `dist` into `C:\PROJECT11\phplus\dist` (can be overridden with `PHPLUS_BUILD_TARGET`).
- Backend (`phplus/main.py`) serves SPA files from `phplus/dist` for `/` and non-API frontend routes.

## 3. Technical Stack
Frontend:
- React + TypeScript + Vite
- React Router
- Recharts (BMI/BP charts)
- Session token stored in `sessionStorage`

Backend:
- FastAPI
- MySQL (PyMySQL)
- JWT (HS256)
- Password hashing with bcrypt (passlib)
- XML parser for health screening files under `phplus/health_screening`

## 4. Main Modules and Functional Flow
### 4.1 Authentication and Role Access
Frontend routes:
- `/login`
- `/dashboard`
- `/health-screening`
- `/engage`
- `/vital-signs`
- `/admin`
- `/qr-join/:qrToken`

Backend auth endpoints:
- `POST /api/auth/register`
- `POST /api/auth/login` (staff)
- `POST /api/auth/admin-login` (admin password)
- `GET /api/auth/me`
- `PUT /api/auth/me`
- `POST /api/auth/change-password`

Role behavior:
- Staff and admin can access protected routes.
- `/admin` route is restricted to users with `admin` role.

### 4.2 Staff Dashboard
Frontend dashboard calls `GET /api/dashboard` and renders:
- greeting and basic profile info
- current BMI and healthy range
- monthly/daily BMI trend
- vital signs (systolic/diastolic)
- medication/allergy block (current backend response set)
- schedule (events/programs/activities) with attendance action

Actions:
- update metrics (height/weight/blood pressure) via `POST /api/health-records`
- attend from schedule via `POST /api/dashboard/schedule/{entity_type}/{entity_id}/attend`

### 4.3 Engage (Events/Programs/Activities)
Endpoints:
- `GET /api/engage/categories`
- `GET /api/engage/items`
- `POST /api/engage/items/{item_id}/join`
- `DELETE /api/engage/items/{item_id}/join` (currently disabled; join-only policy)

Current behavior:
- status is computed by session timing (`Upcoming`, `Live`, `Joined`, `Closed`, `Full`)
- join is allowed only on session date, after start time, before end time

### 4.4 QR Attendance
Frontend route:
- `/qr-join/:qrToken` for participant join via QR link

Endpoints:
- `GET /api/qr-codes/{qr_token}/detail`
- `POST /api/qr-codes/{qr_token}/join`
- `POST /api/qr-codes/generate` (admin)
- `GET /api/qr-codes` (admin)
- `GET /api/attendance-logs` (admin)
- `POST /api/attendance/scan` (scan flow support)

### 4.5 Health Screening (Lab Results)
Endpoints:
- `GET /api/health-screenings`
- `GET /api/health-screenings/{folder_name}/tests`

Current behavior:
- backend reads XML files from `phplus/health_screening/<dated-folder>/`
- user matching is based on IC number suffix (last 4 digits)
- if user `identification_no` is missing or too short, no result is returned

Current local data:
- available health screening folder: `27-03-2025`
- detected XML files: `109`

### 4.6 Vital Signs Detail
Frontend route `/vital-signs`:
- fetches records from `GET /api/health-records`
- displays monthly blood pressure trend (systolic/diastolic)
- falls back to navigation-state data if API fails

### 4.7 Admin Dashboard
Main admin capabilities:
- staff listing: `GET /api/users`
- staff password reset: `POST /api/admin/users/{user_id}/reset-password`
- module CRUD:
  - events: `GET/POST/PUT/DELETE /api/events`
  - programs: `GET/POST/PUT/DELETE /api/programs`
  - activities: `GET/POST/PUT/DELETE /api/activities`
- QR generation and preview
- attendance log filtering + CSV export in UI
- mental health score management:
  - `POST /api/mental-health-scores`
  - `GET /api/mental-health-scores`
